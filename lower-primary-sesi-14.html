Kenapa disebut otomatis?

Karena setelah pembeli memberi sinyal, kasir atau mesin langsung melanjutkan cerita: menghitung, bicara, dan menampilkan struk.

Ceritanya dimulai dari pembeli datang ke toko, memilih barang, lalu menuju kasir.

Cara berpikirnya

Di ScratchJr, kita belum menghitung seperti kalkulator sungguhan. Jadi kita membuat simulasi: angkanya disiapkan dulu, lalu sprite menampilkannya dalam cerita.

Sesi 14

Kapan Pakai Message?

Tanpa message

Semua sprite mulai sendiri-sendiri. Kadang dialog muncul terlalu cepat.

Dengan message

Satu sprite bisa memberi sinyal. Sprite lain baru berjalan setelah menerima sinyal itu.

Ingat aturan warna

Jika memakai send message dan receive message, warnanya harus sama. Kalau warnanya berbeda, pesannya tidak sampai.

Sesi 14

Mini Activity: Hitung Kembalian

Rp20Uang bayar
Rp15Total belanja
Rp5Kembalian

Pembeli belanja Rp15. Pembeli membayar Rp20. Kembaliannya berapa?

Cara cepat

Kembalian = uang bayar - total belanja. Jadi Rp20 - Rp15 = Rp5.

Tempat yang cocok untuk Wait

Pembuka Sesi 14

Sesi ini mengenalkan siswa pada project bertema toko dan mesin kasir. Bahasa yang dipakai dibuat dekat dengan kehidupan sehari-hari: barang, harga, total, uang bayar, dan kembalian.

Target belajarnya bukan membuat kalkulator sungguhan, karena ScratchJr belum memiliki operasi matematika seperti aplikasi coding tingkat lanjut. Targetnya adalah membuat simulasi kasir yang alurnya masuk akal.

Empat kata kunci di slide kiri membantu siswa memahami isi sesi sebelum masuk ke block: barang, harga, total, dan struk.

Tujuan belajar

Slide ini memberi peta belajar yang sederhana. Siswa perlu tahu bahwa project bukan hanya soal menggerakkan sprite, tetapi juga menyusun cerita transaksi yang jelas.

Bagian “membaca harga” dan “menyusun urutan” sengaja ditekankan karena ini menghubungkan coding dengan literasi finansial dasar. Anak belajar bahwa setiap barang punya harga dan pembelian punya total.

Debugging tetap dimasukkan agar siswa terbiasa mengecek project, bukan langsung menganggap project gagal.

Cerita project

Project akan lebih mudah dibuat jika siswa memahami ceritanya dulu. Cerita sederhana: pembeli datang, memilih barang, kasir menghitung, pembeli membayar, lalu mendapat kembalian.

Istilah “otomatis” dijelaskan dengan bahasa anak: setelah ada sinyal, sprite lain melanjutkan tugasnya. Ini membantu siswa memahami kenapa message atau urutan code penting.

Guru dapat mengajak siswa menyebutkan pengalaman sederhana di toko, misalnya membeli roti atau minuman.

Input, process, output

Slide ini memperkenalkan cara berpikir komputasional tanpa istilah yang terlalu berat. Input adalah barang, process adalah kasir mengecek dan menjumlah, output adalah total dan kembalian.

Karena ScratchJr tidak menghitung otomatis seperti spreadsheet, angka harga perlu disiapkan di cerita. Ini penting agar ekspektasi siswa tepat.

Dengan begitu, siswa paham bahwa project mereka adalah simulasi kasir otomatis, bukan mesin penghitung uang sungguhan.

Sprite dan peran

Slide ini memecah project menjadi beberapa peran. Pemecahan ini membantu siswa membuat code per sprite, bukan mencampur semua tugas di satu tempat.

Pembeli bertugas bergerak dan menyebutkan barang. Kasir bertugas menjawab. Barang menjadi informasi harga. Struk atau mesin menjadi tempat menampilkan total.

Jika siswa kesulitan, guru bisa meminta mereka menunjuk sprite satu per satu dan menjawab: “Sprite ini tugasnya apa?”

Menata panggung

Penataan posisi penting karena project ScratchJr sangat visual. Jika semua sprite menumpuk, siswa sulit melihat alur belanja.

Area barang dan area kasir dibuat terpisah agar pembeli punya tujuan gerak yang jelas. Ini juga membantu saat siswa menentukan jumlah langkah Move.

Slide ini dapat menjadi checkpoint awal sebelum coding: background sudah ada, sprite terlihat, dan posisi tidak saling menutupi.

Alur cerita

Urutan cerita adalah tulang punggung project. Siswa kelas 2-3 SD sering bisa membuat sprite bergerak, tetapi perlu bantuan untuk membuat alurnya masuk akal.

Urutan di slide kiri bisa dibaca seperti cerita pendek. Jika urutannya terbalik, misalnya kembalian muncul sebelum bayar, siswa akan mudah melihat bahwa ada yang kurang pas.

Gunakan slide ini sebagai rencana sebelum masuk ke code.

Harga barang

Angka dibuat kecil agar sesuai untuk siswa LP. Harga seperti Rp5, Rp7, dan Rp3 lebih mudah dijumlahkan daripada harga besar.

Quick check membantu mengecek pemahaman penjumlahan sederhana. Jawaban Rp12 berasal dari Rp5 + Rp7.

Untuk project final, siswa boleh mengganti barang dan angka selama totalnya masih sederhana dan bisa dijelaskan.

Sequence

Sequence adalah konsep utama yang terus dipakai di ScratchJr. Block dibaca dari kiri ke kanan, sehingga susunan block sangat menentukan jalannya cerita.

Dengan contoh kasir, sequence terasa nyata: datang dulu, beli dulu, baru total dan kembalian. Anak biasanya lebih mudah memahami urutan melalui cerita sehari-hari seperti ini.

Ini juga menjadi dasar debugging: kalau hasil project aneh, cek dulu urutannya.

Block utama

Block utama dibuat sederhana dan familiar: Green Flag, Move, Say, dan Wait. Ini cukup untuk membuat animasi kasir berjalan.

Message ditambahkan sebagai opsi penting jika project membutuhkan koordinasi antar sprite. Misalnya, pembeli selesai bicara lalu kasir mulai menjawab.

Jika siswa belum siap memakai message, guru bisa menyederhanakan dengan timing dan Wait. Namun message membuat project terasa lebih “otomatis”.

Message sebagai sinyal

Slide ini mengulang konsep message dengan konteks baru. Pada project kasir, message membantu kasir atau mesin menunggu giliran.

Penekanan warna message sangat penting. Send message dan receive message harus memakai warna yang sama. Jika berbeda, sprite penerima tidak akan mulai.

Ini bisa menjadi checkpoint teknis utama ketika project siswa tidak berjalan sesuai rencana.

Kode pembeli

Alur code pembeli dibuat seperti cerita: mulai, berjalan, bicara, lalu mengirim pesan. Ini membantu siswa membaca code sebagai kalimat.

Jumlah Move bisa disesuaikan dengan posisi sprite di project masing-masing. Jika pembeli belum sampai kasir, tambah langkah. Jika terlalu jauh, kurangi langkah.

Bagian Say sebaiknya tidak terlalu panjang agar mudah dibaca di layar ScratchJr.

Kode kasir

Kasir menunggu receive message agar dialognya tidak muncul terlalu awal. Setelah menerima message, kasir menyebutkan total dan kembalian.

Wait disisipkan agar siswa dan penonton punya waktu membaca dialog. Tanpa Wait, percakapan bisa terasa terlalu cepat.

Quick check di slide kiri memastikan siswa paham bahwa kasir mulai setelah menerima message.

Kode mesin atau struk

Jika project memakai sprite mesin kasir atau struk, sprite ini dapat bertugas menampilkan angka total dan kembalian. Ini membuat konsep “output” lebih terlihat.

Dalam ScratchJr, output bisa berupa balon kata. Karena itu, Say digunakan untuk menampilkan “TOTAL: Rp15” dan “KEMBALI: Rp5”.

Bagian ini bisa disesuaikan dengan sample project: jika tidak ada sprite struk, fungsi output dapat dilakukan oleh kasir.

Kembalian

Slide ini menghubungkan project dengan matematika finansial sederhana. Rumusnya dibuat sangat dekat: kembalian = uang bayar - total belanja.

Contoh Rp20 - Rp15 = Rp5 sengaja dipilih agar mudah dihitung siswa kelas 2-3 SD.

Guru dapat meminta siswa memakai jari atau gambar uang sederhana untuk memahami kembalian.

Wait dan tempo cerita

Wait membuat project terasa lebih nyaman ditonton. Pada usia LP, dialog yang terlalu cepat sering membuat siswa mengira code tidak bekerja.

Tempat terbaik untuk Wait adalah setelah dialog penting: setelah pembeli bicara, setelah total muncul, atau sebelum kembalian ditampilkan.

Wait juga membantu siswa belajar bahwa coding bukan hanya “jalan”, tetapi juga mengatur tempo cerita.

Pengujian project

Checklist ini dibuat sebagai asesmen cepat. Siswa bisa mengecek sendiri apakah project mereka sudah memenuhi target dasar sesi.

Project dianggap berhasil jika pembeli bergerak, barang disebutkan, total muncul, kembalian muncul, dan ceritanya runtut.

Jalankan project dari Green Flag, bukan dari tengah-tengah, agar bug terlihat dari awal.

Debugging

Debugging dibagi berdasarkan masalah yang paling mungkin muncul. Jika kasir tidak bicara, fokusnya message. Jika dialog terlalu cepat, fokusnya Wait. Jika pembeli tidak sampai, fokusnya jumlah Move.

Pemisahan ini membantu siswa tidak asal menghapus semua block. Mereka belajar mengecek bagian yang sesuai dengan masalahnya.

Quick check menegaskan kembali aturan warna message karena ini biasanya menjadi sumber bug yang sering terjadi.

Menyimpan dan keamanan digital

Slide ini menutup aktivitas coding dengan kebiasaan kerja yang aman. Siswa perlu menyimpan project dengan nama yang jelas agar mudah ditemukan lagi.

Keamanan digital dibuat sesuai usia: jangan menulis alamat rumah, nomor telepon, password, atau informasi pribadi lain di project.

Nama toko boleh dibuat kreatif, tetapi tetap aman dan tidak memakai data pribadi.

Penutup dan refleksi

Refleksi membantu siswa menyadari bahwa project kasir otomatis membutuhkan urutan, angka, dan kerja sama antar sprite.

Jawaban yang diharapkan adalah message dan urutan yang rapi, karena dua hal ini membuat project terasa otomatis dan mudah diikuti.

Siswa yang selesai lebih cepat dapat diberi challenge: tambah satu barang, ubah harga, atau buat ucapan terima kasih di akhir.
