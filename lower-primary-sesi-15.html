Empat Langkah Debugging

  1. Coba - jalankan project.
  2. Cari - lihat bagian yang membuat masalah.
  3. Perbaiki - ubah bagian yang perlu saja.
  4. Coba Lagi - jalankan ulang untuk mengecek hasil.
Ingat: kalau ada satu bug, kita tidak perlu menghapus semua code. Cari dulu bagian yang membuat masalah.

Hari ini kita jadi Detektif Code

Robot Bit sedang punya masalah. Ia bergerak terus dan tidak berhenti seperti yang kita inginkan. Tugas kita bukan membuat project baru, tetapi mencari bagian code yang membuat masalah.

Kita akan memakai empat langkah sederhana: Coba, Cari, Perbaiki, Coba Lagi. Jadi kalau ada bug, tidak perlu panik. Kita lihat dulu apa yang terjadi, baru memperbaiki bagian yang perlu.

Apa itu infinite loop?

Infinite loop adalah pengulangan yang terus berjalan tanpa berhenti. Bayangkan ada instruksi “jalan terus” tetapi tidak pernah diberi tahu kapan harus berhenti.

Di project Robot Rusak, Bit terus bergerak karena pengulangannya tidak punya batas yang sesuai. Padahal tujuan kita adalah membuat Bit bergerak beberapa kali saja, lalu berhenti.

Repeat Forever tidak selalu salah

Repeat Forever boleh dipakai kalau sesuatu memang harus terus berjalan. Misalnya awan bergerak terus atau kincir terus berputar selama project aktif.

Tapi kalau Robot Bit harus berhenti setelah beberapa gerakan, kita perlu block yang punya jumlah, misalnya Repeat 4. Jadi kita memilih loop sesuai tujuan project.

Jalan terus dan jalan 4 kali

Kalimat “jalan terus” tidak memberi jumlah. Kita tidak tahu kapan harus berhenti. Ini mirip Repeat Forever.

Sedangkan “jalan 4 kali” punya batas yang jelas. Setelah hitungan keempat, kita berhenti. Itulah ide yang dipakai saat memperbaiki Robot Bit.

Lihat dulu sebelum memperbaiki

Code pada slide kiri adalah code starter yang masih rusak. Sebelum mengubah apa pun, jalankan project dan lihat apa yang dilakukan Bit.

Kalau Bit tidak berhenti, cari block yang membuat gerakan terus berulang. Jangan langsung menghapus banyak block. Kita cukup mencari bagian yang membuat masalah.

Empat langkah debugging

Coba berarti jalankan project. Cari berarti lihat bagian yang membuat masalah. Perbaiki berarti ubah bagian itu. Lalu Coba Lagi untuk memastikan hasilnya sudah benar.

Kalau ternyata masih salah, kita boleh mengulang langkah ini lagi. Debugging memang sering dilakukan lebih dari satu kali.

Code setelah diperbaiki

Pada code perbaikan, pengulangan tanpa batas diganti menjadi Repeat 4. Gerakan ke kiri berada di dalam Repeat, jadi gerakan itu dilakukan empat kali saja.

Setelah Repeat selesai, Bit bergerak ke bawah lalu mengatakan bahwa ia sudah tidak rusak lagi. Perhatikan bahwa setelah loop selesai, project bisa lanjut ke block berikutnya.

Cari bukti bahwa bug sudah selesai

Kita tidak cukup hanya berkata, “Kayaknya sudah benar.” Kita perlu menjalankan project lagi dan melihat hasilnya.

Sebelum diperbaiki, Bit terus bergerak. Sesudah diperbaiki, Bit mengikuti jumlah Repeat lalu berhenti atau lanjut ke aksi berikutnya. Itulah bukti bahwa perbaikannya bekerja.

Kalau masih ada masalah

Kalau Bit masih bergerak terus, cek apakah Repeat Forever masih ada. Kalau gerakan terlalu banyak, cek angka pada Repeat. Kalau gerakan tidak ikut diulang, cek apakah block geraknya sudah masuk ke dalam Repeat.

Perbaiki satu bagian, lalu jalankan lagi. Dengan begitu kita lebih mudah tahu perubahan mana yang membuat project menjadi benar.

Selesai memperbaiki Robot Bit

Sebelum menutup project, cek lagi: starter sudah pernah dijalankan, bug sudah ditemukan, Repeat sudah punya jumlah, dan project sudah dicoba lagi.

Kalau semuanya bekerja, simpan project. Setelah itu kamu bisa mencoba challenge dengan mengganti angka Repeat menjadi 2 atau 6, lalu melihat apa yang berubah. Terakhir, kerjakan Checkout Quiz Sesi 15.
